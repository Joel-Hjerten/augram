# Augram.App.Tests

Avalonia headless tests (`Avalonia.Headless.XUnit`) for components, view models and host services, plus `Architecture/` rules on the source itself: no `.axaml` under `src/Augram.App/Components/` may contain a literal colour (ADR-0002 §5b), and every `XField` declaration has a renderer registered under kind `X` (§5c).

**May reference:** `Augram.App` (and everything it references), Avalonia.Headless.XUnit, xunit.

Use `[AvaloniaFact]` for anything that touches a control; plain `[Fact]` for file-system, view-model and host-service tests. `TestAppBuilder` configures the headless app with the real `CompositionRoot` (logs redirected to a temp folder) and exposes its `Services`. To exercise a component, put it in a `Window`, call `Show()`, and inspect it through `GetVisualDescendants()`; bindings apply synchronously on the test (UI) thread. `Support/` holds the fakes (`FakeOptions`, `FakeClipboard`, `FakeRow`).

Single-instance tests (`Hosting/SingleInstanceGuardTests`, `Hosting/InstanceStartupTests`) use the real mutex and pipe under a unique name per test (`Support/InstanceTesting.UniqueName`), never the app's own "Augram"; `InstanceTesting` also holds a name without a pipe (a silent Augram) and plays Augram 0.1's inbound-only listener, and `FakeTakeOverPresenter` answers the take-over dialog. Channel-dependent tests pass `Support/TestBuilds.Dev` or `.Release` instead of relying on how the test run was built.

`Sync/` tests the App side of machine-to-machine sync with no git and no network: `Sync/Support/SyncMachine` is one machine (real stores and coordinator, a temp config folder, a `FakeSyncRepository` on a shared in-memory `SyncRemote`, the store thread on the caller, a `SyncService` over a `ManualSchedule` so the 20 s and 5 min timers fire only when a test says so). A test waits for the worker with `WaitForRuns(n)` and compares counts relative to before (a machine that joined through `SyncDirect` has already pulled once). `FakeSyncJoinPresenter` and `FakeSyncConflictPresenter` answer the dialogs.

`Ignored/` tests the Ignored tab (F5 ignore list): `IgnoredViewModelTests` drives `IgnoredViewModel` over a real `MappingStore` with `FakeFormDialogPresenter` and `FakeConfirmPresenter` (list and summaries per platform, the shared form applying each edit, a refused edit, a change from elsewhere synced into the open form, new, rename, the active box, delete with confirmation, undo and redo); `IgnoredPerCommandTests` the two sub-tabs (plan 0004: each lists its own scope, a Per command entry's form with "Used by" links that open their commands and follow the store, new on each list, Move to Per command and Move to Global with its question, one undo step each, delete's question), `IgnoredModuleTests` the tab's two sub-entries and `IgnoredGalleryTests` the gallery's Per command page; `AppMatcherEditViewModelTests` covers the identification form app groups and ignored apps share, `AppMatcherFinderTests` what a window finder's pick fills in it (this platform's list, once; path and title exact as one change; Use; nothing when the window lacks the value) and `AppMatcherFinderFormTests` the rendered form: which fields have a magnifier, each one dragged onto a window, and on the Ignored tab each pick one undo step of the store. The window finder itself is `Components/WindowFinderTests` (a headless drag outside the test window: live feedback, the pick at the release point, own windows and empty screen, Esc, right-click, unloading) and `Components/WindowProbeTests` (identities read only when the cheap key changes). They run over `Support/FakeWindowSystem` (windows as screen rectangles); no test moves the real pointer or reads a real window. `Components/MasterDetailTests` drives the lookless list-beside-form component in a headless window (rows, the host's selection without an echo, the detail form or the empty text, the button, the active box, the keys, rename in place, the menu's move entry). `Hosting/EnginePauseStateTests` follows a real `EngineHost` over fakes (no hook) into a pause and out of it at stop; `EngineModuleTests` checks that a mapping edit reaches the engine's ignore-list watch.
