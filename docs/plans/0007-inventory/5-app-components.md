# Review: `src/Augram.App/Components/` (+ `tests/Augram.App.Tests/`)

Read: CLAUDE.md, ADR-0002 (§5–5c and the 2026-10-11 amendments), the App README, every `.cs` under `Components/` (144 files, 0 `.axaml`: all templates live in `Themes/`), the Screens that host the big components, the gallery navigation, the UsedBy/Sync/Transfer windows and presenters for cross-checks, and the test tree (180 files). Read-only; nothing changed.

## Map

`Components/` is five different kinds of thing under one folder:

1. **Declarative renderers** (the §5c machinery): `ScreenHost/` (3 `IScreenRenderer`s + registry, assembly-scanned) → `SectionForm/` (`SectionForm` → `SectionView` → `FieldRow`) → `Fields/<Kind>/` (13 `IFieldRenderer`s + `BindingObserver` + registry); `ItemList/` (+`ListRowBuilder`) renders a `ListSpec`, used only by Log, Recognition and the Used-by popup; `TextPanel/`, `Shell/` (tabs over `NavigationRegistry`, `WindowDragArea`), `FormDialog/` (lookless dialog + request + presenter + window).
2. **Editable list components**, each "items in, one `ActionRequested` out, host owns selection": `CommandTree/` (27 files: the tree, its rows incl. the shared base `ItemRow`, menu, keymap, the `CommandHeader` in 9 partials, and the Commands *vocabulary*: `CommandItem`×2, `SectionItem`, `SectionId`, `TriggerKind`/`InputKind` + their wording extensions, `AskingDropdown`), `CommandsWorkbench/` (composes tree + header + `StepList` + group form), `StepList/` (list, `StepRow`, `StepDragReorder`, `StepItem`, `StepPlatformMarker`, picker flyouts), `StepTypePicker/`, `MasterDetail/` (Exclusions: list beside form), `GestureGrid/` (+`GestureTile`, own menu + keymap, `GestureTileItem`), `GesturePicker/` (+presenter + window), `SyncConflictList/` (+row, entries).
3. **Gesture drawing**: `GestureGlyph/` (`GlyphGeometry` recipe, `GlyphStroke` gradient polyline, `GlyphColours`), `GestureDrawArea/` (+`ScreenArea`).
4. **Input-capture controls** that fall back to the window when the engine is off and find their port through an application resource key: `HotkeyCapture/` (box, recorder, `CaptureWindowWatch`, `AvaloniaKeyMap`, `ModifierToggle`, `EngineKeyCapture`), `ButtonDetect/` (`ButtonDetector`, `EngineButtonCapture`), `WindowFinder/` (+`WindowProbe`, accessory factories).
5. **Step forms**: `Steps/<Name>/` (15 `IStepForm`s, `StepFormRegistry` scanned, `StepFormContext`), each building a `FormScreen` rendered by `SectionForm`.

Flow: `Screens/*.Declare` → `ScreenHost` → renderer → component; `CommandsScreen` binds `CommandsWorkbench` → tree/header/steps → step forms → `SectionForm` → field renderers. View models build the projections through factories that live in Components (`CommandItem.From`, `SectionItem`, `StepItem.From`, `GestureTileItem.From`; 18 call sites in ViewModels/Screens/Hosting). ADR §5c's "Gestures grid, command tree, ignored list and step list are four specs, one renderer" never happened: `ItemList` renders read-only tables; the editable lists are bespoke lookless controls.

## Findings (most valuable first)

**1. In-place rename editor implemented twice.** Kind 1. `Components/CommandTree/ItemRow.cs:852-961` (BeginEdit/CancelEdit/StartEditor/CommitOnLeave/OnEditorKeyDown, `:editing`/`:inactive`, `PART_NameEditor`) and `Components/GestureGrid/GestureTile.cs:287-381` are the same logic line for line, including the deferred `Dispatcher.UIThread.Post` commit-on-leave and the "unchanged name raises nothing" rule. Recommend: `GestureTile : ItemRow` (it tolerates a template without `PART_Active`; `CanRename` stays true), deleting the tile's copy. Size S. Risk low (same part names in all four theme templates; `GestureGridTests` covers rename). Keeps behaviour exactly.

**2. Four context-menu + key-binding builders, plus a fifth.** Kind 1. `CommandTree/CommandTreeMenu.cs`, `StepList/StepListMenu.cs`, `MasterDetail/MasterDetailMenu.cs`, `GestureGrid/GestureGridMenu.cs`: identical `Build`/`Item`/`Bind`/`BindKeys` shape (MenuItem with `Tag` = action, `KeyBinding` + `RelayCommand` with the "stand down while editing" `canExecute`), differing only in the entry table and the `Refresh` rules; `ItemList/ListRowBuilder.cs:80-103` is a fifth variant over `ListSpec`. Recommend one generic `ActionMenu<TAction>` under its own `Components/` folder (entries table in, `Refresh(Func<TAction, bool> enabled, visible)`, `BindKeys((gesture, action)[])`), each list keeping only its table and its `Allows` rules. Size M. Risk low. Keeps behaviour.

**3. Two keymaps.** Kind 1. `CommandTree/CommandsKeymap.cs` (instance, per platform, has `RenameAlso` = Enter on Windows, Copy/Paste/Duplicate) and `GestureGrid/GestureGridKeymap.cs` (static, no Enter rename). The view models' messages use one or the other (`GesturesViewModel.cs:174,203` vs 15 sites in `ViewModels/Commands/*`). `MasterDetail` already borrows `CommandsKeymap` from the CommandTree namespace. Recommend fold into one `EditKeymap` in a neutral folder (with finding 2). Size S. Risk low. Not exact: Enter would also rename gestures on Windows unless the grid binds only `Rename` (question 1).

**4. The list-host skeleton is written five times.** Kind 1. `CommandTree.cs:173-188,245-310,319-334`, `MasterDetail.cs:148-199,228-250`, `StepList.cs:100-125,148-220,257-274`, `GestureGrid.cs:87-116,135-172`, `GesturePicker.cs:776-805`: a `PART_Rows` ListBox, an `_applying` flag with `Quietly`, `ApplySelection` by id so the host's selection survives a rebuild without echoing `Select` back, `Rebuild` with keyboard-focus restore (CommandTree 259-279 and MasterDetail 180-199 are near-identical, the 2026-10-07 "Return renamed commands but not groups" fix lives in both), and "right-click selects before the menu opens" in four `OnRowPressed`s. Double-click is handled three different ways (press count via `ItemRow.IsRenameClick`; `ListBox.DoubleTapped` in GestureGrid, GesturePicker and `UsedBy/UsedByWindow.cs:52`). Recommend one `RowListHost` helper by composition (owns the ListBox, selected-id sync, rebuild-with-focus, right-click select, the `IsEditing` key stand-down), each component keeping its row factory and action enum. Size L. Risk medium: focus and selection timing is where the past incidents were (`StepListFocusTests`, `CommandTreeTests`, `MasterDetailTests`, `GestureGridTests`, `GesturePickerTests` all exist and would catch it). Keeps behaviour if done as an extraction.

**5. `ItemRow` is a shared base living in a feature folder.** Kind 2/5. `CommandTree/ItemRow.cs` is the base of `MasterDetail/MasterRow`, `StepList/StepRow`, `SectionRow`, `CommandRow`; MasterDetail and StepList `using Augram.App.Components.CommandTree` only for it and the keymap. Recommend move to `Components/ItemRow/` (with findings 1–3's shared pieces beside it). Size S. Risk low (pure move, namespace edits in src and tests). Exact.

**6. "Dialog chrome implemented once" is implemented four times.** Kind 1. `FormDialog/FormDialog.cs` is the lookless, themed dialog (its doc: "F7: dialog chrome implemented once"; `FormDialogRequest` already allows a message-only confirmation). Yet `UsedBy/ConfirmDialog.cs`, `UsedBy/UsedByWindow.cs:44-69`, `Sync/SyncConflictWindow.cs:30-52` and `Transfer/AugramImportView.cs:25-44` each hand-build the `dialog` DockPanel + `dialog-buttons` + `toolbar` buttons, and each window re-implements Escape in `OnKeyDown` (ConfirmDialog, UsedByWindow, SyncConflictWindow, AugramImportWindow). Recommend: `ConfirmPresenter` becomes a message-only `FormDialogRequest` through `FormDialogPresenter`; `FormDialog` gains a `Content` slot so the three content windows are `FormDialogWindow` hosts. Size M. Risk medium; not exact unless two rules are carried over explicitly: `ConfirmPresenter` answers false without a visible main window (destructive never proceeds unasked) while `FormDialogPresenter` shows ownerless, and `ConfirmDialog.ShowAloneAsync` is used by the take-over question. Crosses into UsedBy/Sync/Transfer (other reviewers' areas).

**7. Modal-owner lookup copied 11 times.** Kind 1. `(Application.Current?.ApplicationLifetime as IClassicDesktopStyleApplicationLifetime)?.MainWindow` followed by "ShowDialog if visible, else Show and await Closed" in `Components/FormDialog/FormDialogPresenter.cs:91-102`, `Components/GesturePicker/GesturePickerPresenter.cs:53-61`, `Sync/SyncConflictPresenter.cs:37-47`, `Sync/SyncJoinPresenter.cs:32-41`, `Transfer/AugramImportWindows.cs:26-35`, `Training/TrainingPresenter.cs:38-45`, `UsedBy/UsedByPresenter.cs:46-54`, `UsedBy/ConfirmPresenter.cs:14`, `Import/ImportPresenter.cs:35`, `Hosting/AppClipboard.cs:12`, `Transfer/TransferFilePicker.cs:72`. Recommend one `Views/DialogOwner` (or `Hosting/`) with `ShowOwnedAsync(window)` / `ShowOwned(window)` and the three deliberate variants kept as named choices. Size S. Risk low. Exact if the variants are kept.

**8. Four resource keys, two publishers, for "a component needs a port".** Kind 1/3. `HotkeyCaptureBox.KeyCaptureResourceKey` (published in `Hosting/EngineModule.cs:149`), `WindowFinder.WindowSystemResourceKey` and `DisplayModeStepForm.DisplayModesResourceKey` (`EngineModule.cs:161-162`), `ButtonDetector.ButtonCaptureResourceKey` (published separately in `App.axaml.cs:206`); each control also has its own explicit-override property (`KeyCapture`, `Capture`, `WindowSystem`, a ctor). The reason (forms and finders are built by assembly scan, without services) is documented only in an `EngineModule` summary. `Steps/OpenApp/OpenAppStepForm.cs:28` instead reads `Hosting.CommandsModule.CurrentPlatform` directly, a component reaching into Hosting. Recommend one `ComponentPorts` resource (the four ports plus the platform) published once from the composition root, one `TryFindResource` helper, and a README paragraph; `OpenAppStepForm` gets the platform through `StepFormContext` or that resource. Size S–M. Risk low. Exact.

**9. `SyncConflictRow` re-implements `AskingDropdown`.** Kind 1. `SyncConflictList/SyncConflictRow.cs:139-205` (`_applying`, `_labelsFor`, labels replaced only when the entry changed, index applied without echo) is `CommandTree/AskingDropdown.cs` by hand. Recommend move `AskingDropdown` to a shared folder and use it. Size S. Risk low. Exact.

**10. `CommandHeader`: one control, nine partials, two of them clones.** Kind 2. ~1,460 lines, 40+ styled properties, ten dropdown/check-box groups, its own `ButtonDetector` and `HotkeyCaptureBox`. `CommandHeader.NotIn.cs` and `CommandHeader.AlsoIn.cs` are the same 60 lines with the name swapped (`CanSetX`, `XText`, `EditX`, `FindXParts`, `ApplyX`). Recommend (a) fold NotIn/AlsoIn into one parameterised row (S, low, exact); (b) consider two child lookless controls, `TriggerEditor` (Hold + Button + DragDistance + Conflict) and `InputEditor` (Input + detector), placed by the header's template, leaving the header with name, kind, category, Use on, version (M–L, medium: template parts move between control themes; `CommandHeaderTests`, `CommandHeaderInputTests`, `DragDistanceGalleryTests`, `TriggerConflictGalleryTests` cover). Question 5.

**11. `CommandItem` does two jobs.** Kind 2. `CommandTree/CommandItem.cs` is the row's projection and the header's: `StepRefusals`, `ChangeRefusals`, `OptionsDragDistancePx`, `StrokeButton` and the whole `CommandItem.Draft.cs` are documented four times as "the view model sets it on the header's item; rows keep it empty". Recommend a `CommandHeaderItem` built from the row item (`With…`) so rows carry none of it, or leave and state it once in the folder README. Size M. Risk medium (the Commands view model builds both; many tests). Exact.

**12. The Commands tab's projection and wording live under Components, not the view model.** Kind 3. `CommandItem.From/LimitLine/VersionLine/TriggerLine/Summarise` (`CommandItem.cs:556-690`), `StepList/StepPlatformMarker.cs` (all F8 wording), `TriggerKindExtensions` (`Hint`, `AnchorWarning`, `FixHint`, `HoldAButton`, `Phrase`), `InputKindExtensions.Hint`, `SectionItem.CountText`, `GestureTileItem.From` (partner selection from `ConfusionPair`s), `StepItem.From`. Recommend either move the `From` factories and wording statics to `ViewModels/Commands/Projection/` leaving plain records in Components, or keep and name the folder's role in its README ("the Commands vocabulary"). Size M (moves only). Risk low. Exact. Question 2.

**13. **14. ## Map gaps (what the READMEs must say)

`Components/README.md`: the five kinds above and which folder is which; the editable-list contract (items in, `ActionRequested` out, host owns selection and it survives a rebuild, `IsEditing` stands the keys down, right-click selects, rename in place through `ItemRow`, the one keymap); the "only asks" contract (`AskingDropdown`, `CommandHeader`: a control never keeps a value the host refused); the `_applying`/`Quietly` echo guard and why; projections `X.From(...)` and who builds them; how a component finds a port (the resource keys, finding 8) and why; `PART_` names and pseudo-classes are the contract with `Themes/` (templates are not here; search both theme files); `Region.Mark`; the Row, Help and Text rules by link; that `ItemList` is the read-only table renderer and the ADR's "four specs, one renderer" is not how it went.

Per folder: `CommandTree/` (the `SectionId` identity model with `Parent` for hold remaps; what each `SectionItem` flag unlocks in the menu; `CommandItem` row vs header fields; draft vs stored and the conflict note), `StepList/` (row reuse when the count is unchanged, `EnsureForm`'s keep/rebuild rule, the drag contract and the click-vs-grip rule, the two pickers), `HotkeyCapture/` (engine vs window-only, mouse-only commit, one-key mode, idle watchdog), `ButtonDetect/`, `WindowFinder/` (screen units per platform, cheap key before identity), `GestureGlyph/` (recipe, gradient by arc length, `ArrowLength` per size from the theme), `GestureGrid/` (partners/duplicates), `Fields/` and `Steps/` (the how-to-add text now in the App README, moved here), `MasterDetail/`, `SyncConflictList/`, `FormDialog/` and `GesturePicker/` (what is lookless, what is a presenter).

Where an agent gets lost today: `ItemRow` and `CommandsKeymap` under CommandTree but used by MasterDetail/StepList; two keymaps; four resource keys published from two places; `CommandItem`'s header-only fields; presenters in two kinds of place; the wording of the Commands tab under Components; no `.axaml` in Components so `PART_` names must be found in `Themes/Default/*.axaml` and `Themes/Wireframe/*.axaml`.
