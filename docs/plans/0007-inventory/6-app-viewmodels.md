# Review: Augram.App ViewModels / Screens / Declarations / Navigation / Views (+ tests)

Read: CLAUDE.md, ADR-0002 (§5–5c, §6, 2026-10-11 amendments), App README, every file in the five folders (SyncViewModel skipped), `UsedBy/`, the Core naming/rules files they lean on, and the test support folders. No edits, builds or git writes.

## Map

- **Three store projections** drive the three editing tabs: `Commands/CommandsViewModel` (16 partials, 2,149 lines, one per Commands sub-tab, over `MappingStore` + `GestureLibrary`), `Ignored/IgnoredViewModel` (4 partials, 491 lines, one per Exclusions sub-tab, over `MappingStore`) and `GesturesViewModel` (over `GestureLibrary`, writes `MappingStore` through `UsedBy/GestureBindings`). Each: subscribe → re-project on the UI thread → `Handle(actionArgs)` → `Guard` a store call → `Message`. Both Commands VMs and both Ignored VMs are singletons sharing one store and one `CommandClipboard`.
- **Edit view models** are form state with no rules: `GroupEditViewModel`, `HoldRemapEditViewModel`, `CategoryEditViewModel`, `IgnoredEditViewModel` (all `From`/`SyncFrom`/`Apply`/`Declare()`), composed over the shared `AppMatcherEditViewModel` (+ `.Picking`, `.WindowDetails`, `AppMatcherFormView`). They live in a `FormDialog` for "new" and in the side panel for "selected" (`CommandsViewModel.GroupPanel/.HoldRemapPanel/.CategoryPanel`, `IgnoredViewModel.Panel`).
- **Check-list dialogs**: `NotInEditViewModel`, `AlsoInEditViewModel`, `Ignored/AllowedForEditViewModel`, `ExportViewModel` (each a `_checked` set + `Declare()`); `SyncJoinViewModel` and `SyncConflictsViewModel` (reused by `AugramImportViewModel` + `.Text`).
- **Settings and diagnostics**: `AppSettingsViewModel` (Options, over `SettingsStore` + `AppState`), `ConfigurationViewModel`, `TrainingViewModel`, `ImportViewModel` (SP.net), `LogViewModel`, `HealthViewModel`, `RecognitionViewModel`, `MainWindowViewModel`.
- **Screens/** turn a VM into a `ScreenDeclaration`: `ComponentScreen` for the three workbench tabs (CommandsWorkbench, MasterDetail, GestureGrid bound by hand in `Build`), `FormScreen` for Options (five `Declare…`), Health and the import review top, `ListScreen` for Log and Recognition. `OptionsSyncSection`/`OptionsConfigurationSection` are sections of Options › Sync.
- **Declarations/** is the vocabulary: `Field` + 13 kinds, `Section`, four screen shapes, `ListSpec` and parts, `IValueBinding`/`DelegateBinding` (property name inferred from the getter expression; empty-name refresh), `ChoiceBinding`.
- **Navigation/**: `NavEntry` tree → `NavigationRegistry`; `AppNavigation.Build` assembles it (three tabs from Hosting modules, two inline); `TabNavigator` switches via `MainWindowViewModel.InitialTabKey`; `ICommandLocator` → `Commands/CommandLocator`.
- **Views/**: `MainWindow` (composes Shell + InspectorOverlay, closing hides, draws its own title bar), plus three unrelated files (`ClickAwayFocus`, `MacDockPresence`, `TakeOverPresenter`).
- Tests are well centralised (`Support/`, `Commands/CommandsTestData`, `HoldRemapTestData`); one fake per port, no duplicated builders found.

## Findings (most valuable first)

**1. Side-panel edit lifecycle written four times** (kind 1). `ViewModels/Commands/CommandsViewModel.GroupPanel.cs:17-107`, `.HoldRemapPanel.cs:18-99`, `.CategoryPanel.cs:16-101`, `ViewModels/Ignored/IgnoredViewModel.Panel.cs:19-107`. Each holds an edit VM + its id + `_applying…`/`_syncing…` flags, a `Project…Panel` (rebuild when another item is selected, else `SyncFrom`), an `On…Edited` (skip while syncing, `Guard(store.Update(edit.Apply(stored)))`, re-sync on a refusal) and a `Detach…`. Differences are parameters: which refusals re-sync (hold remap: any non-name; category: Use on only), which property names to ignore (`GuessText`, `UsedBy`, `AllowedFor`). Recommend: one `PanelEdit<TEdit,TModel,TId>` (ViewModels/) taking `From`, `SyncFrom`, `Apply`, the ignore set and the re-sync policy; the four partials shrink to the policy. Size M. Risk medium: the "form rebuilt only when another is selected so typing keeps focus" behaviour is the thing to preserve; covered by `CommandsViewModelCategoryUseOnTests`, `HoldRemapFormTests`, `IgnoredViewModelTests`. Keeps behaviour.

**2. "Use on" two-toggle sub-form three times** (kind 1). `GroupEditViewModel.cs:34-38,49,64-65,87-93`; `HoldRemapEditViewModel.cs:41-45,65-66,84,102-108`; `CategoryEditViewModel.cs:20-24,45-46,53,61-67`. Same two bools, same `PlatformSet.None.With(Windows,…).With(MacOS,…)`, same `Includes` sync, same `TogglesField("Use on", …)`. Recommend one `UseOnEdit` (observable, `PlatformSet Value`, `SyncFrom(PlatformSet)`, `Field Declare(help)`), help text passed in. S, low, keeps behaviour.

**3. Check-list dialog state four times** (kind 1). `NotInEditViewModel.cs:33,75-83,153-156`; `AlsoInEditViewModel.cs:24,62-70,76-83`; `Ignored/AllowedForEditViewModel.cs:27,64-72,78-92`; `ExportViewModel.cs:31,99-112,139-140`. Each: `HashSet<TId> _checked`, `IsChecked`/`SetChecked` raising one property, `Item(x) → CheckListItem` with a `DelegateBinding<bool>`, "check list or empty NoteField". Recommend a `CheckedSet<TId>` that owns the set and builds `CheckListItem`s; dialogs keep `For`/`Entries`/`Declare`. S–M, low, keeps behaviour (NotIn's live list and `Added` stay in NotIn).

**4. No view-model base class, so projection plumbing repeats** (kind 1, and ADR §5a: "Marshalling to the UI thread is the view model's job, done in one base class"). UI marshalling: `Commands/CommandsViewModel.Projection.cs:26-36`, `GesturesViewModel.cs:274-284`, `Ignored/IgnoredViewModel.cs:167-177` (identical), `SyncViewModel.cs:44` its own `_marshal`. `Guard` (catch `MappingValidationException`/`KeyNotFoundException` → `Message`): `CommandsViewModel.cs:273-290`, `IgnoredViewModel.cs:223-237`, and inline in `GesturesViewModel.cs:94-101,171-179,206-209`. `Message`, `CanUndo`, `CanRedo` declared three times. Recommend `StoreViewModel` base (Message, Guard with the exception set, OnStoreChanged→UI, unsubscribe on Dispose). S–M, low, keeps behaviour. Do this before 5 and 19.

**5. Delete-with-confirm flow six times** (kind 1). `Commands.cs:152-164`, `Groups.cs:37-58`, `HoldRemaps.cs:47-72`, `Categories.cs:48-85`, `IgnoredViewModel.cs:150-165`, `GesturesViewModel.cs:186-210`: `ConfirmAsync(title, question, "Delete")` → `Guard(remove)` → `"Deleted '{name}'. {Undo} undoes it."`. Recommend `DeleteAsync(title, question, Func<string> remove)` on the base from 4. Note the undo word comes from two places, `CommandsKeymap.Current.Undo` and `GestureGridKeymap.Undo`. S, low, keeps behaviour.

**6. `CommandsViewModel` is one class of 2,149 lines** (kind 2; §6 says a 300-line file is a smell, and this is 16 files of one type). Seams already visible: trigger editing (`.Trigger`, `.TriggerDraft`, `.TriggerConflict`, `.Input`: 520 lines, own state `_draft`, needs store/gestures/platform/`WithTriggerHere`) → `TriggerEditor`; the three panels (after 1) → `SectionPanel`; `.Steps` + `NewStep`/`EditableSteps` → `StepEditor`. `CommandsViewModel` keeps dispatch, selection, projection. L, medium (tests build the VM through `CommandsTestData`, so the public surface can stay; the collaborators are internal). Keeps behaviour.

**7. Gesture unbind/retarget is a mapping rule living in App** (kind 3). `UsedBy/GestureBindings.cs:12-84` (called from `GesturesViewModel.cs:200,230`) decides "a command bound to a deleted gesture loses its trigger; on Keep this, retarget unless the group already binds the kept gesture, then unbind". Core does this family of repairs for sync and import (`Core/Sync/SyncDocumentBuilder.cs:169-188`, `Core/Sync/CommandPlacement.cs:78-120`, `Core/Transfer/ImportResolution.cs`) but has no callable rule; `Command.WithGestureReplaced` (`Core/Mapping/Command.Trigger.cs:60`) has no Core caller. Recommend `MappingStore.UnbindGesture(id)` / `RetargetGesture(from, to)` (or `MappingRules`) returning counts; `GestureBindings` goes. M, low–medium. Behaviour question: today each command is its own `UpdateCommand` = one undo step per command; a store method could make it one step (Q1).

**8. A command's "where it is" label built two ways** (kind 1). `UsedBy/UsedByRow.cs:15-22` builds `Group › Category › Command` with its own `Separator`; Core `Mapping/CommandNames.cs:38-47` builds `Group › HoldRemap › Command`. `Ignored/IgnoredViewModel.PerCommand.cs:75` and `Ignored/AllowedForEditViewModel.cs:90` construct a `UsedByRow` only to read `.Label`; `SyncConflictsViewModel.cs:198` uses Core's. So "Used by" drops the hold remap and sync text drops the category. Recommend one Core `CommandNames.Label` that includes the category for Global and the hold remap for apps; `UsedByRow.Label` calls it. S, low; text changes in two spots (Q2).

**9.
