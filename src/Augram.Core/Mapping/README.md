# Core/Mapping

The mapping model (requirements F5, F5a): **app group › command › step**, the matcher that identifies an app, the resolver the engine asks on button-up, and the store that owns the live mapping. Landed in M2 step 1. Persistence lives in `../Config/`; nothing here knows about storage.

## Types

| Type | Role |

## Resolver rule (`CommandResolver.Resolve(mapping, window, trigger)`), in order

1. The window belongs to an **active ignored app** → `Ignored`, reason `ignored app 'Game'`, `IgnoredBy` set; unless (plan 0005, "Also in") an entry without the disable-while-focused mode is named in the "Also in" of a command that matches by steps 2–6 with only such commands counting: it fires, reason `global, also in 'Blender'`. This is the backstop: normally the engine's ignore-list watch has already made the stroke button pass through over the app (`IgnoreList.Under`, the same rule), so no stroke reaches the resolver; one captured on a stale answer still fires nothing.
2. The **first active app group** in document order (Global first, then alphabetical) whose matcher claims the window is *the app group*. Order, not specificity, breaks ties.
3. That group has an **active command whose trigger on this platform matches the press exactly** (`PressedTrigger.Matches`: the same kind, and the keys and buttons held equal the trigger's set under its capture mode; learnings 0003 §3.4) → `Matched`, reason `app override in 'Chrome'`; with no steps it is `override to nothing in 'Steam'` (matched, `Fires` false). There is no fallback to a trigger holding fewer keys, at either level: Shift + Up with only a plain Up bound fires nothing, and a plain Up override in Chrome does not shadow a Global Shift + Up.
4. Else, the group **suppresses globals** → `None`, reason `globals suppressed by 'FF7'`.
5. Else the **Global group's** active command for the trigger → `Matched`, reason `global`.

In 3 and 5 a command whose `NotIn` names an active Ignored › Per command entry claiming the window (`IgnoreList.PerCommandUnder`) is as if it did not exist (plan 0004): an app group's falls through to 4 and 5, and when nothing else fires the reason is `'Zoom In' is not used in 'Spine'`. Step 1 counts only Ignored › Global entries. An inactive Global group gives `None`, `the Global group is inactive`.
6. Else `None`, reason `no command for this gesture` / `no command for wheel up`.

A null window (nothing under the point) skips 1 and 2. `Trigger.None` is `None`, `no trigger`. Inactive groups, commands and ignored apps are invisible throughout, and so are app groups not used on this platform and commands that `AppGroup.IsCommandUsedOn` says are not (F8 "Use on": group AND category AND command), so their trigger falls through as if they did not exist. Commands under a hold remap (F9) are never resolved: their input belongs to the hold remap while its hold key is held. `Reason` is one line meant for the recognition log and the file log as-is.

## Store contract (`MappingStore`)

| Member | Behaviour |
|---|---|
| `Current` | immutable, sorted snapshot (a new instance after every change); `Version` increments with every change, undo and redo included; `Changed` is raised synchronously after each |
| `Global`, `FindGroup(id)`, `FindCommand(id)` → `(Group, Command)?`, `FindIgnored(id)` | lookups; null when absent |
| `UsedBy(gestureId)` | every `(Group, Command)` bound to the gesture, document order: the "Used by…" popup and the delete warning |
| `AddGroup`, `UpdateGroup` (by id, commands and categories included), `RemoveGroup` | Global cannot be removed (`MappingValidationException`); `KeyNotFoundException` for an unknown id |
| `AddCommand(groupId, command)`, `UpdateCommand(groupId, command)`, `RemoveCommand(id)`, `MoveCommand(id, toGroupId)` | one undo step each; a move keeps the id (paste into another group) and keeps the category only by name: the target group's category with the same name (case-insensitive), else Uncategorized; and its hold remap only by hold key: the target group's hold remap on the same key, else it lands an ordinary command without its input (`HoldRemapRules.Moved`); it is refused when its name is taken among the commands of the parent it lands in (rule 2). Commands go in and out of a hold remap through these, with `HoldRemapId` set or cleared |
| `AddHoldRemap(groupId, holdRemap)`, `UpdateHoldRemap(groupId, holdRemap)`, `RemoveHoldRemap(groupId, id)` | F9 (`MappingStore.HoldRemaps.cs`): one undo step each; removing one removes the commands under it (the UI asks first); `KeyNotFoundException` for an unknown id |
| `AddIgnored`, `UpdateIgnored`, `RemoveIgnored` | same shape; changing an entry's `Scope` to Global (or removing it) drops it from every command's `NotIn` in the same step (rule 11) |
| `UpdateCommandAddingIgnored(groupId, command, added)` | plan 0004 step 7, the "Not in" dialog's Save: appends the new ignored apps (Per command entries made by Add app…) and replaces the command naming them, one change and one undo step, refused as a whole |
| `ReplaceAll(document)` | import; validated as a whole first; one undo step |
| `Undo()` / `Redo()` / `CanUndo` / `CanRedo` / `ClearHistory()` | linear history, 100 steps (`State/UndoStack`) |

Every mutation builds the next document and runs it through `MappingRules.ValidDocument`; a failure throws before anything is recorded and the store is unchanged. Mutators return the item as stored (trimmed, sorted into place).

## Validation rules (`MappingRules`)

1. Names are trimmed; empty names are rejected (groups, commands, ignored apps).
2. Group names are unique, case-insensitively (`GestureRules.NameComparer`); command names are unique within their **parent** (Joel, 2026-10-10; `CommandNames`): a command under a hold remap among that hold remap's commands, an ordinary command among its group's ordinary commands ("A command named 'Orbit' already exists under 'Space' in 'Blender'.", "… already exists in 'Chrome'."). Two hold remaps of a group may each have an "Orbit", and so may a hold remap and the group's ordinary commands; ids identify a command everywhere, names only label it. A rename, a move between hold remaps or out of one, and a paste are checked against the siblings where the command lands.
3. Exactly one group has `GroupId.Global`; it is sorted first, never has a matcher and never suppresses globals (normalised, not refused).
4. A bound trigger is used at most once per group (A7; an input once per hold remap, so two hold remaps may both use Left): two commands clash when their triggers on Windows or on macOS (`Command.TriggerFor`, converted or own) overlap (`Trigger.Overlaps`: the same kind and the same buttons and keys, with capture modes that overlap: Either with anything, Before with Before, After with After; learnings 0003 §3.5). `NoTrigger` any number of times. A wheel trigger must hold a button (the stroke button or another one). A button trigger (plan 0005 decision 2) holds a button other than the stroke button and not the stroke button ("'Magnifier' holds the stroke button: a button trigger holds another button, as Right in Right + Left."; "… holds no button: …"), and its Remap step's output is a key ("'Magnifier' has a button trigger: its Remap output must be a key.", `HoldRemapRules`). The normaliser adds the stroke button to a gesture's and a click's set, sets the capture mode to Either when nothing besides the anchor is held, and turns a click holding nothing extra into `NoTrigger`.
5. Ids are unique: groups among groups, commands across the whole document, ignored apps among ignored apps.
6. A regex field that is switched on must compile.
7. Step lists may be empty (override to nothing). Steps themselves are not validated here; a step is whatever its type read.
8. Category names are trimmed, non-empty and unique within their group, case-insensitively ("A category named 'Media' already exists in 'Global'."); category ids are unique within their group (the same name or id may appear in another group). A command whose `CategoryId` is not among its group's categories is normalised to null, never refused.
9. A group, a category and a command are each used on at least one platform ("Use 'Personal' on at least one platform."). Their combination is not checked: a macOS-only command in a Windows-only category is allowed and is used nowhere until one of them changes (the lists say "used nowhere"), so no stored value ever has to change because another did.
10. Hold remaps and the commands under them follow `../HoldRemaps/HoldRemapRules` (README there): hold keys never modifiers and unique per group, tap time 0..2000 ms, never on Global, an input only under a hold remap and only an input there, a Remap step a command's only step; a command under a hold remap the group lacks becomes ordinary, never refused.
11. "Not in" (plan 0004, normalised, never refused): a `NotIn` names Ignored › Per command entries that exist (not Global ones, not a deleted entry), once each, sorted by id, and is empty under a hold remap. "Also in" (plan 0005, the same way): an `AlsoIn` names Global entries without the disable-while-focused mode that exist, once each, sorted by id, and is empty under a hold remap and on a command whose trigger holds the stroke button on both platforms. A Per command entry's `DisableEntirely` is false. A trigger's own drag distance (`TriggerHold.DragDistancePx`) is kept only on a set without the stroke button (`HandsBackDrags`) and must be 1 to 200 px ("The drag distance of 'Zoom In' must be between 1 and 200 px.").

## Categories

A group's `Categories` are sections for its commands. The resolver asks one thing of them: a category's `UseOn` (F8, Joel 2026-10-08) narrows where its commands are used (`AppGroup.IsCommandUsedOn`: group AND category AND command), so a set of Global commands can be kept off one platform in one place; each command keeps its own `UseOn`, and ticking the platform on the category again brings it back. A command's trigger, activity and steps do not depend on its category. Null `CategoryId` is "Uncategorized", which has no settings and limits nothing. There are no category mutators: the UI adds, renames or deletes a category with `UpdateGroup(group with { Categories = …, Commands = … })`, one undo step, and the rules clear the `CategoryId` of every command whose category went away. `MoveCommand` carries a category across groups by name only (ids are per group). Persistence: `categories` on a group (omitted when empty; each with `useOn` when it is not every platform) and `category` on a command (omitted when null), see `../Config/README.md`. Import: `Augram.Import.StrokesPlus` (`CategoryReader`, and `MappingImport.Merge` merges them by name).

## Threading

Single-writer: the UI thread mutates the store. The engine worker takes `Current` as a snapshot when `ConfigSession.DocumentChanged` tells it the document moved, and calls `CommandResolver` against that snapshot; it never calls a mutator. No locks inside. `MatcherRegexCache` is the one shared mutable thing and is a `ConcurrentDictionary`.
