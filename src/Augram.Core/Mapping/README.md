# Core/Mapping

The mapping model (requirements F5, F5a): **app group › command › step**, the matcher that identifies an app, the resolver the engine asks on button-up, and the store that owns the live mapping. Landed in M2 step 1. Persistence lives in `../Config/`; nothing here knows about storage.

## Types

| Type | Role |
|---|---|
| `GroupId`, `CommandId`, `CategoryId` | strongly typed Guids, stable across renames and moves (F8); `GroupId.Global` is a fixed value every install agrees on |
| `AppMatcher` | F5 app identification: `WindowsProcessNames` and `MacProcessNames` (F8 per platform, any-of, case-insensitive, the primary field; `Matches(window, platform)` uses this platform's list, else the other list's guess from `KnownApps`; names with none for this platform and no guess match nothing here, never everything; `EffectiveProcessNames`, `IsGuessedOn`), each list with a regex toggle (`WindowsProcessNamesAreRegex`, `MacProcessNamesAreRegex`, 2026-10-09: each entry a pattern; a pattern list gives no guess), `ProcessPath` + `ProcessPathIsRegex` (Windows) and `MacProcessPath` + `MacProcessPathIsRegex` (2026-10-09: a path names one platform's file, so `PathFor(platform)` is the only one consulted there), `Title` + `TitleIsRegex` (Windows, the root owner's) and `MacTitle` + `MacTitleIsRegex` (`TitleFor(platform)`), StrokesPlus.net's per-window fields (2026-10-09, Windows: `RootTitle`, `ParentTitle`, `ControlTitle`, `OwnerClass`, `RootClass`, `ParentClass`, `ControlClass`, each + `…IsRegex`, read from `WindowIdentity.Levels`; one list, `WindowFields`, for matching and validation; on macOS the window has none, so a matcher that sets one matches nothing there), `ClassChain` (the older Windows escape hatch, kept so configs that use it match as before: every listed class must appear in `WindowIdentity.ClassChain`; an entry may list alternatives with `\|`, "Progman\|WorkerW"), `IgnoreWhenFullScreen` (A21). Set fields are ANDed, unset ones ignored, nothing set matches nothing. Regexes: case-insensitive, culture-invariant, 100 ms timeout, cached by pattern in `MatcherRegexCache` (internal); an invalid pattern is no match here and a validation error at save |
| `Trigger` | closed set with value equality: `Trigger.GestureTrigger(GestureId)`, `Trigger.WheelTrigger(WheelDirection)`, `Trigger.ClickTrigger` (the stroke button clicked while holding keys or buttons, SP.net's no-gesture action), `Trigger.NoTrigger` (`Trigger.None`, a command not bound yet), each with a `Hold` (F1 combinations, Joel 2026-10-09). Factories `ForGesture`, `ForWheel`, `ForClick` (a click holding nothing extra is `None`) normalise the hold; `WithHold`, `Normalised`, `IsSameKind`, `Overlaps` (A7), `NeedsStroke` (gesture and click), `IsBound`; `Describe(names)` for log lines ("Shift + this gesture", "Right + wheel up") |
| `TriggerHold`, `HoldCapture` | the "while holding" set: `Buttons` (`Capture/HeldButtons`: the stroke button and physical ones), `Keys` (Ctrl, Alt, Shift, Win as `KeyModifiers`), `Capture` (Either, Before, After; SP.net's "Capture Modifiers"). `Default` = the stroke button alone. Without the stroke button (a wheel trigger only) each button held is an anchor and the others join its press. `Matches(PressHold)` is SP.net's exact predicate (learnings 0003 §3.4); `Overlaps` the A7 rule (§3.5); `ForStrokeButton` reads an explicit stroke-button flag as the stroke button; `Describe(names, strokeImplied)` |
| `PressedTrigger` | what one press fired, as the engine saw it: the kind (recognised gesture, wheel direction, `Trigger.Click`) and the `PressHold`; `Matches(configured)`; `Of(trigger)` is the press a configured trigger describes (for callers holding a trigger) |
| `TriggerConversion` | a trigger as it reads on the other platform (Joel, 2026-10-09: keys convert like hotkeys): Windows Ctrl ↔ Mac Cmd, Alt = Option, Shift stays; a Windows trigger holding Win, or a Mac one holding Cmd and Ctrl, has none ("needs a macOS version"). `Same`, `To`, `None(reason)`, `IsConverted`, `Explain` |
| `Command.TriggerFor(platform)`, `TriggerPlanFor`, `WithTriggerFor`, `HasOwnTriggerOn`, `WithGestureReplaced` | the trigger across platforms: the own version's trigger where it has one, else the original converted from `Origin` (no conversion while the command has no origin yet); changing it on the other platform makes it that platform's own, the way steps work (the own version is made from the converted steps); `UsesGesture` and `WithGestureReplaced` cover the own trigger too |
| `AnchorPlanner` | the per-app anchor plan (Joel, 2026-10-09): `For(mapping, window, platform, strokeButton)` / `ForGroup`: which buttons are held back over a window (an active command applying there holds them without the stroke button) and which join each anchor's press; `UsesButtons` says whether the engine needs a plan per window at all. The engine's pointer watch asks it off the hook thread |
| `Command.UseOn` | F8 "Use on" for one command (both by default): a command not used on a platform is absent there and its trigger falls through (an app group's to Global); `IsUsedOn(platform)` is its own value only, the whole rule is `AppGroup.IsCommandUsedOn` (below); refused when used nowhere |
| `CommandStep` | the F8 envelope: `Step` (an `IStep`), `AuthoredOn`, `IsActive`; `ForPlatform(platform)` = what runs there (the step itself where authored, else the type's best-guess `StepConversion`) |
| `CommandVersion`, `Command.OwnVersion` | F8 (Joel, 2026-10-07): a command's own steps for the platform it was not authored on (`Platform`, `Steps`, `BasedOn` fingerprint, `ChangedAt`, and since 2026-10-09 `Trigger`: that platform's own trigger, null while it uses the original's converted). `Command.Origin`, `StepsFor(platform)` (what a platform shows and edits), `PlanFor(platform)` (`PlannedStep`s: what runs, each step as stored and as it runs there), `WithStepsFor(platform, steps, now)` (the original on its platform, else the own version, made on the first edit and counting as checked), `ConvertedFor` (the start of an own version), `WithoutOwnVersion`, `WithOwnVersionChecked`, `IsOwnVersionStale` (the original's `Fingerprint` moved on), `IsOverrideToNothingOn` |
| `KnownApps` | F8: well-known apps' executable names on Windows and macOS (chrome.exe ↔ Google Chrome, explorer.exe ↔ Finder, …); `Guess(names, to)`; never stored, so a better table helps every group at once |
| `PlatformSet` | F8 "Use on": `Windows`, `MacOS`, `All`; `Includes(platform)`, `With(platform, bool)` |
| `Command` | `Id`, `Name`, `Trigger`, `IsActive`, `Steps`, `Note` (read-only free text; the importer keeps a script there), `CategoryId` (null = Uncategorized). `IsOverrideToNothing` = no steps |
| `AppGroup` | `Id`, `Name`, `IsActive`, `SuppressGlobals` (SP.net "No Global Actions"), `UseOn` (F8, both by default; a group not used on a platform never matches there; Global is always everywhere; `IsUsedOn(platform)`), `Matcher` (null for Global), `Commands` sorted by name, `Categories` sorted by name (empty by default). `FindCommand`, `FindCategory`, `CategoryOf(command)`. **`IsCommandUsedOn(command, platform)` is the one "Use on" rule for a command** (F8, Joel 2026-10-08): its group, its category (when it has one) and itself must all include the platform; `EffectiveUseOn(command)` is that AND, `UseOnLimitFor(command)` the group's and category's part alone (what the command header shows as boxes the command cannot set). The resolver and every list ask these, never `Command.IsUsedOn` alone. `AppGroup.EmptyGlobal` |
| `CommandCategory` | `Id`, `Name`, `UseOn` (F8, Joel 2026-10-08; both by default; applies to every command in it on top of the command's own; `IsUsedOn(platform)`; refused when used nowhere): a section of one group's commands (Joel, 2026-10-07; SP.net's per-application Categories). The Commands › Global tab is organised by them the way app groups organise app commands; most app groups have none. See "Categories" below |
| `IgnoredApp` | `Id`, `Name`, `IsActive`, `Matcher`, `DisableEntirely`: false = "gestures off over this app", true = "disable while focused" (the same over its windows, and Augram switches off while it has focus) |
| `IgnoreList` | the ignore list's rules (F5; SP.net's Ignore List), pure: `Under(mapping, window, platform)` = the first active ignored app (either mode) claiming the window under the pointer (its stroke button passes through; the same as `CommandResolver.FindIgnored`); `PausedBy(mapping, focused, platform)` = the first active "disable while focused" app claiming the focused window; `WatchesPointer` / `WatchesFocus` = an active entry (of that mode) can match on this platform; `CanMatchOn(matcher, platform)` = something is set, and executable names have this platform's own or a known-app guess. The engine's ignore-list watch asks these off the hook thread (`../../Augram.Engine/README.md`, "Ignore list") |
| `MappingDocument` | `Groups` (Global first, then by name), `Ignored`; `Empty`; `Global`; `AllCommands()` |
| `MappingRules` | the business rules and the normaliser (`ValidDocument`); nothing else re-implements them |
| `CategoryRules` | the category part of those rules, called by `MappingRules` for every group; also `FindByName(group, name)` and `Carried(id, from, to)` (the category a command takes into another group) for the store and the importer's merge |
| `MappingValidationException` | a rule was broken; the message is fit to show the user |
| `CommandResolver`, `CommandResolution`, `ResolutionOutcome` | the decision on button-up, see below |
| `MappingStore` | the store: the single mutable owner of the mapping for the running app |

## Resolver rule (`CommandResolver.Resolve(mapping, window, trigger)`), in order

1. The window belongs to an **active ignored app** → `Ignored`, reason `ignored app 'Game'`, `IgnoredBy` set. This is the backstop: normally the engine's ignore-list watch has already made the stroke button pass through over the app (`IgnoreList.Under`, the same rule), so no stroke reaches the resolver; one captured on a stale answer still fires nothing.
2. The **first active app group** in document order (Global first, then alphabetical) whose matcher claims the window is *the app group*. Order, not specificity, breaks ties.
3. That group has an **active command whose trigger on this platform matches the press exactly** (`PressedTrigger.Matches`: the same kind, and the keys and buttons held equal the trigger's set under its capture mode; learnings 0003 §3.4) → `Matched`, reason `app override in 'Chrome'`; with no steps it is `override to nothing in 'Steam'` (matched, `Fires` false). There is no fallback to a trigger holding fewer keys, at either level: Shift + Up with only a plain Up bound fires nothing, and a plain Up override in Chrome does not shadow a Global Shift + Up.
4. Else, the group **suppresses globals** → `None`, reason `globals suppressed by 'FF7'`.
5. Else the **Global group's** active command for the trigger → `Matched`, reason `global`. An inactive Global group gives `None`, `the Global group is inactive`.
6. Else `None`, reason `no command for this gesture` / `no command for wheel up`.

A null window (nothing under the point) skips 1 and 2. `Trigger.None` is `None`, `no trigger`. Inactive groups, commands and ignored apps are invisible throughout, and so are app groups not used on this platform and commands that `AppGroup.IsCommandUsedOn` says are not (F8 "Use on": group AND category AND command), so their trigger falls through as if they did not exist. `Reason` is one line meant for the recognition log and the file log as-is.

## Store contract (`MappingStore`)

| Member | Behaviour |
|---|---|
| `Current` | immutable, sorted snapshot (a new instance after every change); `Version` increments with every change, undo and redo included; `Changed` is raised synchronously after each |
| `Global`, `FindGroup(id)`, `FindCommand(id)` → `(Group, Command)?`, `FindIgnored(id)` | lookups; null when absent |
| `UsedBy(gestureId)` | every `(Group, Command)` bound to the gesture, document order: the "Used by…" popup and the delete warning |
| `AddGroup`, `UpdateGroup` (by id, commands and categories included), `RemoveGroup` | Global cannot be removed (`MappingValidationException`); `KeyNotFoundException` for an unknown id |
| `AddCommand(groupId, command)`, `UpdateCommand(groupId, command)`, `RemoveCommand(id)`, `MoveCommand(id, toGroupId)` | one undo step each; a move keeps the id (paste into another group) and keeps the category only by name: the target group's category with the same name (case-insensitive), else Uncategorized |
| `AddIgnored`, `UpdateIgnored`, `RemoveIgnored` | same shape |
| `ReplaceAll(document)` | import; validated as a whole first; one undo step |
| `Undo()` / `Redo()` / `CanUndo` / `CanRedo` / `ClearHistory()` | linear history, 100 steps (`State/UndoStack`) |

Every mutation builds the next document and runs it through `MappingRules.ValidDocument`; a failure throws before anything is recorded and the store is unchanged. Mutators return the item as stored (trimmed, sorted into place).

## Validation rules (`MappingRules`)

1. Names are trimmed; empty names are rejected (groups, commands, ignored apps).
2. Group names are unique, case-insensitively (`GestureRules.NameComparer`); command names are unique within their group.
3. Exactly one group has `GroupId.Global`; it is sorted first, never has a matcher and never suppresses globals (normalised, not refused).
4. A bound trigger is used at most once per group (A7): two commands clash when their triggers on Windows or on macOS (`Command.TriggerFor`, converted or own) overlap (`Trigger.Overlaps`: the same kind and the same buttons and keys, with capture modes that overlap: Either with anything, Before with Before, After with After; learnings 0003 §3.5). `NoTrigger` any number of times. A wheel trigger must hold a button (the stroke button or another one). The normaliser adds the stroke button to a gesture's and a click's set, sets the capture mode to Either when nothing besides the anchor is held, and turns a click holding nothing extra into `NoTrigger`.
5. Ids are unique: groups among groups, commands across the whole document, ignored apps among ignored apps.
6. A regex field that is switched on must compile.
7. Step lists may be empty (override to nothing). Steps themselves are not validated here; a step is whatever its type read.
8. Category names are trimmed, non-empty and unique within their group, case-insensitively ("A category named 'Media' already exists in 'Global'."); category ids are unique within their group (the same name or id may appear in another group). A command whose `CategoryId` is not among its group's categories is normalised to null, never refused.
9. A group, a category and a command are each used on at least one platform ("Use 'Personal' on at least one platform."). Their combination is not checked: a macOS-only command in a Windows-only category is allowed and is used nowhere until one of them changes (the lists say "used nowhere"), so no stored value ever has to change because another did.

## Categories

A group's `Categories` are sections for its commands. The resolver asks one thing of them: a category's `UseOn` (F8, Joel 2026-10-08) narrows where its commands are used (`AppGroup.IsCommandUsedOn`: group AND category AND command), so a set of Global commands can be kept off one platform in one place; each command keeps its own `UseOn`, and ticking the platform on the category again brings it back. A command's trigger, activity and steps do not depend on its category. Null `CategoryId` is "Uncategorized", which has no settings and limits nothing. There are no category mutators: the UI adds, renames or deletes a category with `UpdateGroup(group with { Categories = …, Commands = … })`, one undo step, and the rules clear the `CategoryId` of every command whose category went away. `MoveCommand` carries a category across groups by name only (ids are per group). Persistence: `categories` on a group (omitted when empty; each with `useOn` when it is not every platform) and `category` on a command (omitted when null), see `../Config/README.md`. Import: `Augram.Import.StrokesPlus` (`CategoryReader`, and `MappingImport.Merge` merges them by name).

## Threading

Single-writer: the UI thread mutates the store. The engine worker takes `Current` as a snapshot when `ConfigSession.DocumentChanged` tells it the document moved, and calls `CommandResolver` against that snapshot; it never calls a mutator. No locks inside. `MatcherRegexCache` is the one shared mutable thing and is a `ConcurrentDictionary`.
