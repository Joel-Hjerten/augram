# Augram.App

The Avalonia desktop app: tray, settings workbench, shared components, dev gallery. MVVM with `CommunityToolkit.Mvvm`; views are XAML plus a near-empty code-behind; view models are disposable projections over Core/Engine stores (ADR-0002 §5, §5a). Screens are *declared* as section/field trees and list specs, rendered by generic lookless components whose look comes from a theme (§5b, §5c).

This page is the map: each folder's README says what lives there, which type to use for which job, and the behaviour with Joel's decisions. The rules every folder follows are below ("Rules of the road"), then how to add the common pieces.

**May reference:** `Augram.Core`, `Augram.Engine`, `Augram.Platform.Windows`, `Augram.Platform.MacOS` (only the composition root, `CompositionRoot.cs` and `Hosting/Modules/`, plus the four documented macOS exceptions: `MacStatusItem` in `Tray/`, `MacDock` in `Hosting/MacDockPresence` and `App.Launch.cs`, `MacLaunchEvent` in `App.Launch.cs`, `MacWindowGlass` in `Themes/WindowBackdrop`; ADR-0002 §2), `Augram.Import.StrokesPlus` (only `Import/`, `ViewModels/ImportViewModel`, `Hosting/Modules/ConfigModule` for `UpgradeImportedSteps`, and the dev gallery name it), `Augram.Sync.Git` (only `Hosting/Modules/SyncModule` names it), and the Avalonia / CommunityToolkit.Mvvm / Microsoft.Extensions.DependencyInjection packages, plus Velopack (only `Program` names it; `Hosting/README.md`, "Packaging and releases"). `CompositionRoot.cs` is the one place services are registered; nothing else calls `new` on a service.

**Must never contain:** business rules, application state that outlives a window (stores and the engine own it; `AppState` only projects two settings for the tray), P/Invoke, or SharpHook.

## Rules of the road

- **Theme rule.** A component never names a colour, font, margin or icon. It uses a token inside its ControlTheme in `Themes/<Theme>/` (a colour or corner as `{DynamicResource …}`, so a theme switch and the corner setting reach it; a size or spacing as `{StaticResource …}`; [learnings 0008](../../docs/learnings/0008-the-glass-look.md)), or a class (`field-editor`, `help`, `section-title`, `toolbar`, `primary` (the accent button; a button with `IsDefault` looks the same), `cell`, ...) that the theme styles. `tests/Augram.App.Tests/Architecture/ComponentColorTests` fails the build on a literal colour under `Components/`.
- **Text rule (Joel, 2026-10-11).** A text takes a role class from `Themes/Default/Text.axaml` (heading, title, group, body, secondary, badge, mono, or an older class listed there), never a size or weight of its own; the role table lives in that file. `Architecture/TextRoleTests` holds it.
- **Gallery rule.** A component is not done until `DevGallery/GalleryNavigation` shows it in its states with fake data. Same change, same review.
- **Help rule (Joel, 2026-10-09).** A field's or a section's help is an ⓘ after its label or title (`TextBlock.help-icon`, the text in its tooltip), never a line of text under it, so a form row is one line tall. The same goes for a list's or a dialog's instructions (the Gestures tab, the Global and Apps lists, the Exclusions list, the Steps list, the gesture picker, the sync conflict dialog): an ⓘ after the title. Warnings and state notes (a trigger's "Not saved yet", an anchor warning) and empty states stay text, since they must be seen without hovering. `SectionFormTests.HelpIsAnInfoMarkWithItsTextInTheTooltip` holds it for forms, `Architecture/HelpTextTests` for the theme templates. A field kind whose editor should take the whole editor column (the identification form's `PatternField`) says so with `Field.StretchesEditor`; the row then carries `stretch-editor` and the theme stretches it.
- **This platform's side rule (plan 0010, Joel 2026-10-12).** Wherever a value has a Windows and a macOS side (a "Fields for" or "Steps for" switch), only the side of the platform Augram runs on is edited; the other shows read-only with "Edit on Windows" (or macOS). Which side is in view is a `ViewModels/PlatformSideView`, UI state only, opening on this platform. The one way to change the other side from here is a whole-list replace the user asks for (a command's Copy from), one undo step.
- **Row rule.** Every list row looks the same everywhere (Joel, 2026-10-07). A row component's template wraps itself in `Border Classes="row"` with its content line in `Grid Classes="row-line"` (`row-line indented` for a command under its section) and sets no padding, margin, height or frame of its own; controls inside a row use the row classes (`expander`, `row-active`, `row-glyph`, `trigger-badge`). The metrics are the `Row.*` tokens (`Row.Padding`, `Row.IndentedPadding`, `Row.ControlSize`, `Row.GlyphSize`); item-list cells use `Row.Padding` and `Grid.list-row` the same minimum height. `tests/Augram.App.Tests/Architecture/RowMetricsTests` fails the build when a `*Row` template sets its own spacing.
- **Declaration rule.** Screens never hand-lay XAML. If a screen needs something the vocabulary lacks, add a field kind and its renderer, not a `CustomField` or a one-off view (`Architecture/OneHomeFormsTests` holds it for `Screens/`).
- **One-home rule (plan 0007).** Before writing code in a folder, read its README and use the type it names for the job. A second implementation of a listed job (a `Dispatcher.UIThread.Post` outside `Hosting/UiThread`, a `Window` that is not a `DialogWindow`, a list handling its own selection, …) fails an architecture test that names the home; the list, and how to add a guard after a new fold, is [docs/reference/one-home-guards.md](../../docs/reference/one-home-guards.md).
- **State rule.** View models forward intents to stores and services; they hold UI-only state (selected tab, filter choice). Deleting a view model loses nothing.

## How to add…

**A field kind.** (1) `Declarations/XField.cs`: a sealed record deriving from `Field` with `Kind => "X"`, a `IValueBinding<T>` and the `[CallerFilePath]`/`[CallerLineNumber]` parameters. (2) `Components/Fields/X/XFieldRenderer.cs`: `IFieldRenderer` with `Kind => "X"` that builds the editor and keeps it in step with the binding through `BindingObserver.Attach`. It is found by assembly scan; nothing else is edited. (3) If the editor is a new templated control, give it a ControlTheme in `Themes/Default/Forms.axaml`. (4) Add it to the gallery's SectionForm page. `FieldKindCoverageTests` checks the `XField` → `"X"` convention.

**A component.** `Components/<Name>/<Name>.cs` deriving from `TemplatedControl` (properties in, events out, named `PART_*` parts), a `ControlTheme` keyed `{x:Type ns:Name}` in `Themes/Default/Forms.axaml` or `Lists.axaml`, a gallery page, a `README.md` in its folder, and `Region.Mark` on anything the inspector should name.

**A step type's form.** `Components/Steps/<Name>/<Name>StepForm.cs`: an `IStepForm` with `TypeKey => <Name>StepType.Instance.Key` whose `Build(current, changed)` returns a `SectionForm` over a declared `FormScreen`; every binding setter builds the new step record and calls `changed`. It is found by assembly scan (`StepFormRegistry`), so nothing else is edited; `StepFormRegistryTests` fails while a built-in type has no form. Add it to the gallery's StepForms page.

**A search box on a list.** A declared list: `Search:` on its `ListSpec` (a `ListSearch` over a `SearchText` property of the view model). A list component: a `SearchText` property two-way bound to `Components/SearchBox/SearchBox` in its template, the rule `SearchQuery` where the view model projects its items, a `Find` action on `EditKeymap.Find`, and the view model in `Hosting/HiddenWindowReset` (`Components/SearchBox/README.md`).

**A screen.** `Screens/<Name>Screen.cs` with `Declare(viewModel)` returning a `FormScreen`, `ListScreen`, `TextScreen` or `ComponentScreen` (one shared component filling the tab, bound to the view model in `Declare`; the Gestures grid). A new screen *shape* needs an `IScreenRenderer` under `Components/ScreenHost/` (also found by scan).

**A tab or sub-tab.** One `NavEntry` from the tab's module (`Hosting/Modules/<Tab>Module.NavEntry`) pointing at the screen's `Declare`, listed in `Navigation/AppNavigation.cs`. Keys are unique across levels; `Shell.SelectedKey` can select any of them.

**A theme.** Copy `Themes/Default/` to `Themes/<Name>/` (renaming `Default.axaml` to `<Name>.axaml`), change its tokens and ControlThemes, add the name to `ThemeSelector.Names`, and set `ThemeSelector.Active`.
