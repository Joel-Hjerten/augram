# Overlay

The stroke trail (F6): the engine's `IStrokeTrail`, drawn on the UI thread. CLAUDE.md's invariant 6 is this folder's contract: the overlay never covers the screen while idle and is never shown unless its click-through style has been verified.

| Job | Use | Notes |
|---|---|---|
| The trail on Windows | `TrailOverlayWindow` | An Avalonia window; below. |
| The trail over a platform's native surface (macOS: `MacTrailPanel`) | `NativeTrailOverlay` over `ITrailSurface` | Registered when the platform registers an `ITrailSurface` (`Hosting/Modules/EngineModule`). |
| Hand points from the engine worker to the UI thread | `TrailBuffer` | Append under a lock; at most one post until the UI thread takes the frame. |
| Draw the stroke | `TrailCanvas`, `TrailFrame` | |
| Show or hide after reading the style back | `OverlayStylePolicy` + `OverlayStyleDecision` | Over the port's `OverlayStyleReport`. |

## Why the overlay is a Window, not a component

`Overlay/TrailOverlayWindow` is the one piece of UI with no declaration, theme or gallery entry. It is a top-level: it must cover every monitor, sit above every app, never take focus and never take a click, which are window properties (`Topmost`, `ShowActivated = false`, `IsHitTestVisible = false`, the Win32 extended styles re-applied through `IOverlayWindowStyle` after `Show()`, learnings 0001 B2). Its colour, width and opacity are user settings (F6), not theme tokens, so the theme rule does not apply. It is **never full-size while no stroke is in progress** (decision 2026-10-06, after a shown-and-empty instance that was not click-through blocked the mouse): the first stroke's first frame applies the native styles, shows the window, re-applies and reads them back (`IOverlayWindowStyle` returns an `OverlayStyleReport`; `OverlayStylePolicy` says show or hide). Between strokes the window stays shown but is **parked**: shrunk to one pixel at the virtual screen's origin, cleared, still click-through and non-activating (`TrailOverlayWindow.Park`), because hiding it left the previous stroke in the retained surface and it flashed on the next stroke (2026-10-06). The next stroke paints into the parked window first and then grows it, so its first full-size frame is already the new stroke. If the OS reports the window as not click-through it is hidden at once, an `overlay` Error is logged and the trail is a no-op for the rest of the run; a 1 s watchdog hides a window still full-size 3 s after its stroke ended (`CheckIdle`, also an Error). The damage of a wrong style is bounded to one stroke. `EngineModule.Start` creates the window but never shows it, and skips the engine entirely under `--no-engine` / `AUGRAM_NO_ENGINE=1` (`EngineKillSwitch`). Trail calls arrive on the engine worker and go through `TrailBuffer`: append under a lock, post at most one `Dispatcher.UIThread.Post` until the UI thread has taken the frame. Pen width = `Trail.WidthPx` × the scaling of the screen under the stroke start (÷ the window's own scaling, since the window spans monitors). The first rendered segment is timed from `Begin` via `RequestAnimationFrame`, logged as `overlay` / `Trail first frame` and contributed to health as `OverlayFirstFrameMs`.

**macOS: `Overlay/NativeTrailOverlay` over `MacTrailPanel` (2026-10-09).** An Avalonia window never shows over another app's full-screen Space, so on macOS the trail is a native non-activating panel (`Platform.MacOS` README) and `NativeTrailOverlay` keeps the window's rules around it: the same `TrailBuffer`, nothing native until the first stroke, **every** stroke's first frame verifies the panel (`ITrailSurface.Verify` → `OverlayStylePolicy`) before it covers the display under the stroke start, then sets the style, covers, draws, and orders it in only if it was hidden, so the first full-size frame is already the new stroke. Not click-through → hidden, `overlay` Error, no-op for the run, as for the window. Between strokes it is cleared and parked at one point (still ordered in); the same 1 s watchdog hides a panel left full-size 3 s after its stroke. Log lines as for the window (`Overlay style verified` once per new style text, `Overlay area` once per new area with `surface=native`, `Trail first frame`), except that the first frame is timed to the moment the path is handed to Core Animation, not to a rendered frame. The width is points (AppKit scales it).
