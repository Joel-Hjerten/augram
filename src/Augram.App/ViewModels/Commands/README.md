# ViewModels/Commands

The Commands tab's view models: `CommandsViewModel` (one per sub-tab, Global and Apps, over `MappingStore` and `GestureLibrary`; a singleton, so the expanded sections survive a window close), the edit view models its side panel and dialogs show, and the helpers they share. Rules are Core's (`MappingRules`, `CategoryRules`, `HoldRemapRules`, `StepOffer`); this folder finds the words and the store call.

## The search (plan 0009)

`CommandsViewModel.SearchText` is UI-only state like `ShowOtherPlatforms`, two-way bound from the tree's box through the workbench. `.Projection` keeps the sections before the search (`_allSections`, after the platform filter) and `Sections` after it (`CommandSections.Narrow`, decision 4: a section matching by name with all its commands, a matching command alone under its section, both expanded, the rest hidden; on the Apps tab a command's category tag counts as the second level; a shown hold remap keeps its group's header open). The selection, the header and the side panel read from the sections before the search, so a selected row the search hides keeps its panel (decision 5); clearing the box leaves the saved expanded set as it was before the search, except that a row selected *during* the search gets its section opened, so it is in sight (Joel, 2026-10-12: a row selected before the search in a collapsed section stays collapsed). While searching, a header toggle leaves the saved expanded set alone. `Hosting/HiddenWindowReset` empties the text when the main window hides (decision 8).

## Where an intent goes

`Handle(CommandTreeActionEventArgs)` (the tree and the header) and `Handle(StepListActionEventArgs)` (the step list) clear the message and run the intent inside `Guard`. The view model keeps the dispatch, the selection and the projection, and the intents of the tree; three internal collaborators own the rest, each with what the view model lends it through `ICommandsHost` (the message line, `Guard`, the selection, `ShowSelected`, `Reveal`, `ShowForm`, implemented explicitly so the public surface is unchanged):

| Collaborator | Owns | State |
|---|---|---|
| `TriggerEditor` (`.Draft`, `.Conflict`) | the header's trigger and input intents, the trigger draft, Swap and Take it; asked for the header (`WithDraft`) and for the trigger a step is offered against (`DraftedTrigger`) | the draft, its only state |
| `StepEditor` | the step list's intents (`Dispatch`), the step offer, `EditableSteps` | none: the expanded step is the view model's `SelectedStepIndex` |
| `SectionPanel` | the side panel's three forms, each a `PanelEdit`, and their edits (`Show` at the end of every selection projection) | the three `PanelEdit`s |

`CommandLookups` (`store.RequireCommand/RequireGroup/RequireHoldRemap`) is the one lookup with the "no longer exists" words, shared by all four. New code goes to its owner: a trigger or input edit to `TriggerEditor`, a step intent to `StepEditor`, a side-panel form to `SectionPanel`; no `CommandsViewModel` partial declares the draft, a `PanelEdit` or a step offer again.

Which file holds an intent:

| Intent (`CommandTreeAction`) | Partial | Store call |
|---|---|---|
| Select, ToggleExpanded, ToggleOtherPlatforms | `CommandsViewModel.cs`, `.Projection` | none (UI state); the projection rebuilds sections (`CommandSections`, the one place that cuts the mapping into sections) |
| NewSection, Rename/Delete/ToggleActive of a section | `.Sections` → `.Groups`, `.Categories`, `.HoldRemaps` | `AddGroup`/`UpdateGroup`/`RemoveGroup`; a category is an `UpdateGroup` of its group; `UpdateHoldRemap`/`RemoveHoldRemap`. Deleting asks first (`StoreViewModel.DeleteAsync`). |
| NewCommand, Rename/Delete/ToggleActive of a command, Copy, Paste, SetCategory | `.Commands` | `AddCommand`, `UpdateCommand`, `RemoveCommand`; Paste names through `FreeNames`/`NameScope` and carries the category with `CategoryRules.Carried` |
| NewHoldRemap, Copy of a hold remap | `.HoldRemaps` | `UpdateGroup` (the hold remap and its commands as one step) |
| SetTriggerKind/Hold/WheelDirection/Button, SetInputKind/Input, PickGesture | `TriggerEditor` → `.Draft` | `UpdateCommand` through `SaveTrigger`, the steps fitted by `HoldRemapRules.FittedTo` (`WithTriggerHere`) |
| SwapTrigger, TakeTrigger | `TriggerEditor.Conflict` (Take it selects the other through `ICommandsHost.Reveal`) | one `UpdateGroup` exchanging the two commands' triggers |
| SetUseOn, MarkOwnVersionChecked | `CommandsViewModel.cs` | `UpdateCommand` |
| ShowStepsFor (view only), CopyStepsFromOtherPlatform | `CommandsViewModel.Steps.cs` | none; `UpdateCommand` with `Command.WithoutOwnVersion` or `WithOwnVersionAsOriginal` |
| EditNotIn, EditAlsoIn | `.NotIn`, `.AlsoIn` (dialogs `NotInEditViewModel`, `AlsoInEditViewModel`; their ✕ on an unused entry is `RemovableEntries`, one for both) | `UpdateCommand`, or `UpdateCommandChangingIgnored` when Add app… made entries or ✕ removed some |
| Export | `.Export` | none (`StoreViewModel.ExportAsync`) |
| Undo, Redo | `CommandsViewModel.cs` | `Undo`/`Redo` |
| Step intents (`StepListAction`) | `.Steps` → `StepEditor` | `UpdateCommand` with `WithStepsFor`; new steps from `StepOffer.NewStep`; a refused edit hands the list the stored steps again |
| An edit in the side panel's form | `SectionPanel` | `UpdateGroup`, `UpdateHoldRemap`, `UpdateGroup` of the category's group |

## The side panel

While a section row (not a command) is selected, the panel shows its form: an app group's (`GroupEditViewModel`), a hold remap's (`HoldRemapEditViewModel`) or a category's (`CategoryEditViewModel`), each through a `ViewModels/PanelEdit` held by `SectionPanel`. **The form is rebuilt only when another section is selected**, so typing never loses focus or caret; for the same section the stored values are synced in (undo, a rename in the tree), never the form's own edit. A refused name keeps the typed text; a refused value a box cannot keep (both Use on boxes unticked, a hold key already used) is put back with `PanelEdit.Sync`. The edit view models validate nothing; their "Use on" is a `ViewModels/UseOnEdit`.

## The trigger draft

A trigger edit the rules refuse waits as the selected command's draft (`TriggerEditor.Draft`) instead of snapping back:

| State | How it gets there | What happens next |
|---|---|---|
| No draft | the start; any accepted save | an edit is saved at once (`TrySaveTrigger`: one store edit, none when nothing changes) |
| Draft kept | an edit the rules refuse (`KeepDraft`: the stored trigger and the drafted one) | the header shows it with its note (`RefusalOf`); the next edit starts from it (`DraftedTrigger`) |
| Draft with a conflict | refused only because another command of the group uses it here | the note offers Swap and Take it (`TriggerEditor.Conflict`) |
| Settled | Swap or Take it | one `UpdateGroup`; the draft is gone |
| Dropped | another selection; the command gone; its stored trigger changed (undo, sync); the rules now accept it (`WithDraft` saves nothing, it just stops showing) | back to no draft |

Only the header shows a draft; the row keeps the stored trigger. The header's item is a `CommandHeaderItem` (`Components/CommandHeader/`), built from the selected row by `HeaderItem` (`.Projection`): the draft, the step refusals, the Options drag distance and the stroke button live only there.

## Commands tab (F5a, F5, F3 picker, F8 markers; plan 0001 M2; Global / Apps split, Joel 2026-10-07)

The tab has two sub-tabs, **Global** (`commands.global`) and **Apps** (`commands.apps`), as StrokesPlus.net keeps Global actions and app actions apart. Both are `CommandsScreen` (one `CommandsWorkbench` filling the sub-tab) over their own `CommandsViewModel`, constructed with a `CommandsScope`; the logic is one class, and the scope only decides the sections (`CommandSections`) and the words. **Apps** has one section per app group (Global left out), and in a group that has categories (Photoshop) each command row carries its category as a small tag; no sub-headers. **Global** has one section per category of the Global group, by name; every Global command is in one, and **Uncategorized** is an ordinary category among them (Joel, 2026-10-11: "make a regular group just named Uncategorized"), which Core makes for a command left without one (`CategoryRules`, `../../../Augram.Core/Mapping/README.md` rule 8): renamed, deleted, set, exported like any other, and kept when emptied; a category has no active toggle and no app definition, and selecting a category shows its form in the side panel: name and **Use on** Windows / macOS (Joel, 2026-10-08; see CommandsViewModel below).

`CommandsModule.Register(services)` is the tab's slice of the composition root (the gesture picker and form dialog presenters, `TabNavigator`, the shared `CommandClipboard`, the two view models as keyed singletons by `CommandsScope`, each given the `SettingsStore` when there is one and following the stroke button and the drag distance itself, `ICommandLocator`); `CommandsModule.NavEntry(services)` is the tab entry with its two sub-entries. It expects `MappingStore`, `GestureLibrary`, the training session and the `IConfirmPresenter` to be registered and falls back to an empty mapping, the starter set and presenters of its own when they are not (tests, gallery). Register it after `GesturesModule`; without it each sub-tab says so instead of failing the window.
