# ViewModels/Ignored

The Exclusions tab's view models ("Exclusions" in the UI since plan 0005, "Ignored" in the code and keys): `IgnoredViewModel`, one per sub-tab (Global, Per command, While holding; singletons over the one `MappingStore`, sharing its history with the Commands tab), its form `IgnoredEditViewModel`, the Allowed for dialog `AllowedForEditViewModel`, and `IgnoredModes` (the two modes' words). The rules are Core's (`IgnoreList`, `MappingRules`); the list's row summary is `AppMatcher.Summary(platform).Text`.

## While holding (plan 0012)

The third sub-tab, **While holding** (`ignored.whileholding`, a third keyed `IgnoredViewModel`), lists entries whose summary says what holding passes through here ("While holding Alt, S · AfterFX.exe", "Nothing to hold yet · …"). The form (`IgnoredEditViewModel.WhileHoldingTitle`) is name, active, the note **On Global too** while an active Global entry shares an executable name with it on this platform (decision 9; `IgnoredEditViewModel.GlobalNote`, the host's), then the identification. Under it, in the `MasterDetail`'s footer, the **Ignore gestures while holding** card (`Components/HeldInputList`), driven by `IgnoredViewModel.WhileHolding`:

| Intent (`HeldInputListAction`) | Store call |
|---|---|
| ShowSide (the "Ignore for" switch; a `PlatformSideView`, opens on this platform, back to it when another entry is selected) | none |
| Add (recorded or picked), Paste (the input copied with Copy, kept in the view model) | `AddHeldInput` on this platform |
| Delete, Reorder | `RemoveHeldInput`, `MoveHeldInput` on this platform |
| CopyFromOtherPlatform (either side, shown while there is an own version) | `CopyHeldInputsFromOtherPlatform` on the side in view |
| CopyTo (a row of the other side, shown while that side is its own) | `CopyHeldInputFromOtherPlatform` |
| Undo, Redo | `Undo`/`Redo` |

Edits other than the switch and the Copies reach the store only while this platform's side is in view; the first one on an inferred side says the side is its own now. Each row names its input in the side's words with its F8 marker (`StepPlatformMarker.For(WhileHoldingInput, …)`) and, for a hold key of a hold remap for the same app, Core's warning (`HoldKeyConflicts.ForEntry(…).OnEntry`). The hold remap's form shows the other half (`HoldRemapEditViewModel.HoldKeyWarning`, set by `Commands/SectionPanel` from `ForHoldRemap`). **Move** is between Global and Per command only: a While holding entry has no Move to (its inputs exist only on that list), and none moves onto it.

## The search (plan 0009)

`IgnoredViewModel.SearchText` is UI-only state, two-way bound from the `MasterDetail`'s box; `Project` keeps the entries whose name or summary matches (`SearchQuery.Matches(name, summary)`, decision 3). A hidden selected entry keeps its form. `Hosting/HiddenWindowReset` empties the text when the main window hides.

## Where an intent goes

`Handle(MasterDetailActionEventArgs)` clears the message and runs the intent inside `Guard`:

| Intent (`MasterDetailAction`) | Partial | Store call |
|---|---|---|
| Select | `IgnoredViewModel.cs` → `.Panel` | none; the side panel shows the entry's form |
| New | `IgnoredViewModel.cs` (`IgnoredEditViewModel` as an `IDialogForm`) | `AddIgnored` |
| Rename, ToggleActive | `IgnoredViewModel.cs` | `UpdateIgnored` |
| Move (to the other list) | `.PerCommand` (asks first when commands name the entry) | `UpdateIgnored`; Core's normalisation drops it from their Not in / Also in in the same step |
| Delete | `IgnoredViewModel.cs` (`StoreViewModel.DeleteAsync`) | `RemoveIgnored` |
| Undo, Redo | `IgnoredViewModel.cs` | `Undo`/`Redo` |
| An edit in the side panel's form | `.Panel` | `UpdateIgnored`; leaving Also in lists says so (`.AllowedFor`'s `LeftAlsoIn`) |
| Allowed for's Change… | `.AllowedFor` (`AllowedForEditViewModel`, an `IDialogForm` with a `CheckedSet`) | `SetAllowedFor`, one step, nothing when nothing changed |

## The side panel

The selected entry's form lives in a `ViewModels/PanelEdit`: rebuilt only when another entry is selected, so typing keeps focus; for the same entry the stored values are synced in, and its "Used by" (Per command: the commands naming it in their Not in) and "Allowed for" (Global: the commands naming it in their Also in), both Core's `MappingDocument.UsersOf`, are re-read on every store change. Those two lists and the identification's guess are the host's, so they are never taken for an edit. The links read `CommandNames.Label` ("Global › Media › Zoom in") and open the command through `Navigation/ICommandLocator` when there is one.

The code keeps "Ignored": `IgnoredApp`, `IgnoreList`, `IgnoreScope`, `IgnoredViewModel`, `IgnoredEditViewModel`, `IgnoredModes`, `IgnoredModule`, `IgnoredScreen`, the tab keys (`ignored`, `ignored.global`, `ignored.percommand`) and `mapping.ignored` in the config file. Core's own messages (a rule's "An ignored app named …", the export's contents line, sync repairs) still say "ignored app" until Core changes them.

**Hold remaps and exclusions** (plan 0005 decision 7: they never use the stroke button, so a Global entry leaves them working; a "Disable while focused" entry stops them while it has focus). The screen says it where it is read: the Global list's ⓘ (`IgnoredModes.HoldRemapsInTheseApps`, with a sentence on Also in), a Global entry's form, as a **Hold remaps** note after Mode that follows the mode (`IgnoredModes.HoldRemaps`: "Hold remaps still work in this app: they never use the stroke button." or "Augram is off while this app has focus, hold remaps included."), and a hold remap form's ⓘ, which ends "Works even where the app is on Exclusions › Global." (`HoldRemapEditViewModel.WorksOverExclusions`).

SP.net's Ignore List: apps Augram stays out of. The tab has two sub-tabs (Joel, 2026-10-10: "under ignored we could basically have global and apps again"), **Global** (`ignored.global`) and **Per command** (`ignored.percommand`), each an `IgnoredScreen`, one `MasterDetail` filling it over its own `IgnoredViewModel` (`IgnoredModule`: keyed singletons by `IgnoreScope`, process-lifetime; `IgnoredModule.NavEntry` is the tab with its sub-entries). Both lists are one list in the model (`IgnoredApp.Scope`), so names are unique across them. **Global** is the ignore list as it was: each entry by name with its active box and a summary, the mode and what it matches on this machine ("Gestures off over this app · blender.exe", "Disable while focused · nothing on macOS", "… · Blender (guessed)"); selecting one shows its form beside the list, which is the app group form's identification part (`AppMatcherEditViewModel`: the same fields, the guess shown for both platforms since an excluded app has no Use on) under a first section of name, active and **Mode** (`IgnoredModes`: "Gestures off over this app" or "Disable while focused", a button radio over `IgnoredApp.DisableEntirely`). **Per command** ("Per command apps", **New app**; its ⓘ: "Apps listed here change nothing on their own; a command that names one in its Not in does nothing over it and holds no button back there. …") lists the entries a command's Not in can name, the summary saying who uses it ("Used by 2 commands · Spine.exe", "Not used yet · krita.exe"); the form (section "Per command app") has name, active and **Used by ⓘ** instead of a mode, then the same identification: the commands whose Not in names the entry, "Global › Media › Zoom in", "Chrome › Zoom" (`UsedByRow.Label`, as the Gestures tab's Used by names them; "inactive" after a switched-off command), each a link (`LinksField`, `Button.link`) that opens it on the Commands tab through `ICommandLocator` (the Commands module's, resolved when the view model is made; without one the names are plain text), or "none". The links follow the store while the form is open (`IgnoredEditViewModel.UsedBy`, set by the host and never applied as an edit). A Global entry's form has **Allowed for ⓘ** after Mode (plan 0005 decision 7; `.AllowedFor`): the commands whose Also in names it, as the same links (`IgnoredEditViewModel.AllowedFor`), shown only in the plain mode. Its **Change…** (Joel, 2026-10-11: set it from the app's side too; the row's accessory, `Components/Fields/Links/LinksAccessory`) opens `AllowedForEditViewModel` in the form dialog: the commands that can work over an excluded app (`MappingRules.CanWorkOverExcluded`), "Global › Eyeris › magnifier" with the trigger after it ("Right + Left", "· inactive"), the allowed ones ticked, or a note when none can be; Save is one `MappingStore.SetAllowedFor`, one undo step ("'Blender' is allowed for 2 commands now. Ctrl+Z undoes it."), and nothing when nothing changed. Also in the plain mode only; switching the entry to "Disable while focused" drops it from their Also in in the same step (Core's normalisation) and the message line says so ("'Blender' disables Augram while focused now, so it left the Also in of 1 command. Ctrl+Z undoes it."), and **Move to Per command** asks first while commands name it ("'Blender' is allowed for 1 command; on Per command it leaves their Also in, and Augram works over Blender again. Move?"). Each edit applies at once, one undo step each, as on the Apps tab's group panel; a refused edit shows the rule on the message line. New opens the same form in a `FormDialog` and makes the entry on the sub-tab's list; rename in place (rename key or double click); delete asks first (`IConfirmPresenter`; on Per command "Delete 'Spine' from Per command? The 2 commands naming it in their Not in work over it again.") and the store's undo brings it back; the undo keys use the mapping store's one history. **Move** between the lists is the right-click menu's **Move to Per command** / **Move to Global** (`MasterDetail.MoveLabel`, `MasterDetailAction.Move`; `.PerCommand`): one `UpdateIgnored` of the entry's `Scope`, one undo step. To Per command, it asks only while commands name the entry in their Also in (above); a "Disable while focused" mode is dropped by Core's normalisation and the message line says so. To Global, while commands name the entry it asks first ("'Spine' is used by 2 commands; on Global it stops all of Augram over Spine and leaves their Not in. Move?", **Move**), since Core's normalisation drops it from their Not in in the same step (undo brings both back). The moved entry leaves this sub-tab's list and its selection. Look and keys follow the Commands tab: same column widths, the shared row frame and `Row.*` metrics (`MasterRow`), `EditKeymap`.

What the modes do is the engine's (`src/Augram.Engine/README.md`, "The watch"): over an excluded app's windows the stroke button passes through untouched (in both modes); a "disable while focused" app also pauses Augram while it has focus. `EngineSettingsLink` tells the engine about every mapping change, so an edit here takes effect without moving the pointer. `EnginePauseState` follows `EngineHost.PauseChanged` on the UI thread (`EngineModule.Start` links it to a started engine; under `--no-engine` it stays empty) and `AppTray` puts the app's name in the tooltip.
