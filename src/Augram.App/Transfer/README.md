# Transfer

The App's part of F8 export and import of Augram files (plan 0003): the dialogs, the file pickers and the review. The format, the scopes, the matching and the merge are Core's ([Core/Transfer](../../Augram.Core/Transfer/README.md)).

## Which type for which job

| Job | Use | Notes |
|---|---|---|
| Export from any entry point | `IExportPresenter` / `ExportPresenter` | Over `ViewModels/ExportViewModel` in the shared form dialog. |
| Import an Augram file | `IAugramImportPresenter` / `AugramImportPresenter` | Reads, then the review. |
| The platform's save and open dialogs | `ITransferFilePicker` / `TransferFilePicker` | The open dialog takes a `FileOpenRequest`; the StrokesPlus.net import uses it too (`Import/`). |
| The review window | `IAugramImportWindows` / `AugramImportWindows`, `AugramImportWindow` + `AugramImportView` | Over `ViewModels/AugramImportViewModel`; the top half is `Screens/AugramImportScreen`. |

## Export and import of Augram files (F8; plan 0003 steps 3–4, 2026-10-10)

`Hosting/Modules/TransferModule` registers the file picker, both presenters, the import's windows and `ConfigurationViewModel`; it expects the `ConfigSession`, `IImportPresenter` and `IEventLog`.

**Entry points.** Options › Sync › **Export and import** (`Screens/OptionsConfigurationSection`, after Sync; `OptionsScreen.DeclareSync`'s `configuration`; "Configuration" before plan 0006's sub-tabs): "Augram file" with **Export…** (everything preselected) and **Import…**, "StrokesPlus.net" with the StrokesPlus.net import (also still on the Gestures toolbar), and a "Last result" line once something ran. **Export…** on an app group's or a Global category's right-click menu in Commands (that group, or Global, preselected) and on the Gestures toolbar (gestures only). The tray is unchanged. Each entry point shows the presenter's outcome line where it is: the Options line, the Commands or Gestures message line.

**Export** (`ExportPresenter`). `ExportViewModel.Declare()` in the shared `FormDialog` ("Export", confirm **Save…**): Scope as a button radio (Everything / Gestures only / Selected); under Selected the `CheckListField` "App groups": Global first, the app groups by name, the excluded apps, each with a detail ("2 commands · 1 hold remap · Windows only", "excluded app"); "In the file" (`TransferContents`: "options, 90 gestures, Global, 19 app groups, …"); "Typed text" when steps may hold private text ("3 steps type text or run command lines; they are in the file as written. Do not share it if they hold passwords."). Save… is disabled while Selected has nothing ticked. Then the save picker (`TransferFilePicker`: "Augram files (*.augram.json)", `Exporter.SuggestedFileName`, starting in the folder last picked this run; a name typed without `.json` gets `.augram.json`) and `TransferSerializer.Write` through a temp file and a move (`ExportPresenter.WriteAsync`). It works on one snapshot, `ConfigSession.Document`. Logs Info `export` / `Exported Augram file` with the scope, the contents line and the private-text count; a failed write is a Warning and "Could not save x: …".

**Import** (`AugramImportPresenter`). The open picker ("Augram files (*.augram.json)", "JSON (*.json)", all files), `TransferSerializer.TryRead`: a file that cannot be read, is not Augram JSON, was written by a newer Augram or breaks a rule is one message ("Blender.augram.json was not imported. The file was written by a newer Augram (schema version 5); …", Warning `import`) and changes nothing. Otherwise the review, `AugramImportWindow` over `AugramImportView` over `AugramImportViewModel`, modal to the main window:

- **Top** (`Screens/AugramImportScreen`, declared): under the file's name (the import's help in its ⓘ) "In the file", "Compared with yours" ("New: 1 app group, 1 hold remap, 2 commands · Same as yours: 1 gesture · Different: 1 command"), "Nothing to import" ("Everything in this file is already here.") when the plan is empty, "Matched" (one line per item matched by name, hold key or shape, at most 12 then "…and N more."), **Also use its options** (only when the file has options; off), **Every differing item**: a dropdown and **Apply to all** (each row that offers the choice takes it; Keep both is for gestures and commands, so an app group's row keeps its own), "After the import" (the repairs and notes the result needs under the current choices, recomputed on every change), "File notices", and "Not imported" if the stores kept moving.
- **The differing items**: the sync's `SyncConflictList` over `SyncConflictsViewModel` (built with the import's help and the preview's names), columns "Yours" / "In the file", rows "Gesture · with Blender.augram.json", Keep mine by default.
- **Cancel / Import**, Import disabled while the plan is empty. Import applies the reviewed plan on the UI thread (`ImportResult.ApplyTo`: one undo step per store that changed, so Undo on the Gestures tab and on the Commands tab each take their part back); when a store moved since the review opened (a sync), it is refused and the import plans again from the stores with the same choices (keyed by item), up to three plans in all (Core's `ImportApplier`, which the view model calls once). Then the window closes and a message gives the summary ("Imported from Blender.augram.json: 1 app group, 1 hold remap and 2 commands added; 1 command changed.") and the repairs, one per line; the summary is also the Options line. Logs Info `import` / `Imported Augram file` with `SyncCounts`, whether options were taken, the repair and note counts and how often it planned again; never content or the file's name.

Tests (`tests/Augram.App.Tests/Transfer/`) run the view models over an in-memory `ConfigSession` and the presenters with `FakeTransferFilePicker`, `FakeFormDialogPresenter` and `FakeAugramImportWindows`; no test opens a picker or touches the real config.
