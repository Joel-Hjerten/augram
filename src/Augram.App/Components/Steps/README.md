# Steps

One parameter form per step type (ADR-0002 §4): `<Name>/<Name>StepForm`, an `IStepForm` found by scan (`StepFormRegistry`; `StepFormRegistryTests` fails while a built-in type has none). `Build(current, changed)` returns a `SectionForm` over a declared `FormScreen`; a form that adapts to its command takes a `StepFormContext` (its trigger here). How to add one: the App README, "How to add… A step type's form".

| Type | Job |
|---|---|
| `StepFormState<TStep>` | The value a form edits and its one edit path: `Emit` normalises (optional), drops an edit that changes nothing, tells `Accepted`, calls `changed`, refreshes what `Refreshed`/`OnEdit` registered. `Bind` makes a field's binding (its inspector name read from the getter). Delay, Media key, Type text, Run, Scroll, Hotkey and Remap use it. |
| `StepFormRegistry`, `IStepForm`, `StepFormContext` | The scan, the contract, the command context. |

Key and modifier editors come from `Capture/HotkeyChoices`. Not on `StepFormState` yet: HDR (it emits an edit that changes nothing, as Delay and Media key did), Window and Display mode (they re-declare their form when it changes shape), Open app (an observable form state).

## The step forms (from the Commands tab)

**Step forms** (`Components/Steps/<Name>/`, App README, "How to add…"): Window (operation dropdown labelled by the summaries; width and height only for Set size, starting at 1280×720), Delay (milliseconds), Media key (dropdown), Hotkey (capture field; under it the "Per keyboard layout" switch (plan 0011 decision 3): on, one row per keyboard layout the OS has installed, from `ComponentPorts.KeyboardLayouts` (a constructor taking an `IKeyboardLayouts` serves tests and the gallery), labelled by the layout's name and holding a capture field for that layout's own shortcut, empty until set; a layout the step holds that is no longer installed shows by its id with Remove on the line under it; off drops every layout shortcut in one edit, and the rows hide; then Ctrl/Alt/Shift/Win toggles each with an "R" right-hand toggle and the key dropdown, editing the main shortcut. Every row goes through the form's one `StepFormState.Emit`, so a layout row with no key is dropped by `Normalized()` as Remove would. The form re-declares itself when its shape changes and when the layouts port it shows reads differently after `ComponentPorts` is re-published (the composition root does so on a layout change), so the key names and the rows follow the active layout (decision 6)), Type text (the text in a multi-line `TextField` (`Multiline`: Enter adds an LF line break on every platform, long lines wrap, the editor grows to `Editor.MultilineMaxHeight` and then scrolls) and the method as a dropdown, "Unicode (works with most apps)" or "Press keys (for games; US layout)"), Run (Program with Browse… beside it on one line, taking a path, a bare name or a link; Arguments; Start in; "Run as administrator" on Windows only; "Hidden window"),Display mode (Resolution, Refresh and Display dropdowns: "Auto (keep current)" first, then what the connected displays offer, resolutions largest first and the chosen resolution's rates highest first as "119.88 Hz", the step's own value always listed; `DisplayModeChoices` builds the lists; the displays come from the application's `ComponentPorts.DisplayModes`, which `FormServices.Publish` sets also under `--no-engine` because reading modes changes nothing; a constructor taking an `IDisplayModes` serves tests and the gallery), HDR (Toggle / On / Off and the Display dropdown), Scroll (Direction dropdown, "Left (sideways)" and "Right (sideways)" for side-scrolling; Notches 1–20; "Keys held" as one row of four check boxes named by `HotkeyText`, Ctrl/Alt/Shift/Win on Windows and Ctrl/Opt/Shift/Cmd on macOS), Clear clipboard (one note: nothing to set), Imported (read-only: method, description, parameters as "name: value" lines, and the "not supported yet" sentence), Remap (offered under a hold remap, see "Hold remaps" in `ViewModels/Commands/README.md`, and on a button trigger, see "Button triggers" there: Output Button / Key / Wheel, on a button trigger Key only (a stored Button or Wheel output stays listed so it can be changed), with its own ⓘ and the note "Pressed when the trigger fires and held while both buttons are down; released when either is released." ("Wheel … for a wheel input only" in its ⓘ); for a button the Button dropdown (Left, Right, Middle, X1, X2) and "Keys held" as one row of four check boxes; for a key the capture field (key, modifiers and their sides in one press), a Key dropdown and the four modifiers as `ModifierToggle`s with their "R", as the Hotkey form's; for a wheel the Direction (sideways included) and "Keys held"; then the note "Held while the input is held; Shift/Ctrl only around a button's press." A kind change keeps the modifiers and brings back the last button, key or direction chosen in the form; a kind's own editor acts only while the output is that kind, since a hidden dropdown's renderer echoes its value back on every refresh).
