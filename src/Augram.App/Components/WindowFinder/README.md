# WindowFinder

The drag-to-identify magnifier (F5): press, drag onto a window, release, and `Picked` names it. `WindowProbe` asks `IWindowSystem` (in the window system's units: pixels on Windows, points on macOS) cheaply while hovering and for the identity on release. `WindowFinderAccessory` builds the magnifier and the Use button a declared form puts before a field. The window system comes from `ComponentPorts` unless `WindowSystem` is set.

## Window finder (F5 app identification; SP.net's crosshair; Joel 2026-10-09)

Drag-to-identify on the identification form app groups (Commands › Apps) and excluded apps (Exclusions tab) share, and on a command's Not in dialog (Add app…, plan 0004: the picked window's app becomes an Exclusions › Per command entry; see "Drag distance, Not in and Also in" in `ViewModels/Commands/README.md`). Press a magnifier with the left button, drag it onto any window, release: the window under the pointer fills the form. `Components/WindowFinder/WindowFinder` is the magnifier: while dragging the pointer is captured, the cursor is a crosshair, `:finding` is set and a popup above the magnifier says what is under the pointer (`HoverText`: "chrome.exe · Google Chrome", or what a field's finder would take: the path, the title, the classes, or why there is none). Released over another app's window it raises `Picked` with the `WindowIdentity`; over Augram's own windows (settings window, dialogs, the popup itself), over nothing, or after Esc, a right-click or a lost capture it picks nothing, and the release never reaches the window underneath.

- **On the form** (`AppMatcherEditViewModel` + `.Picking` + `.WindowDetails`, 2026-10-09: StrokesPlus.net's App Definition, Joel): a **Fields for: Windows | macOS** switch (`AppMatcherFormView`, view state only, so a flip is never an edit; it opens on this machine's platform) over one row per field, each a `PatternField` (field kind `Pattern`: text box, magnifier, Use Regex on one line, `Grid.pattern-line`): Executable (comma-separated names; an empty box shows the known-app guess in grey), Executable path and Window title on both platforms, Root, Parent and Control title and Owner, Root, Parent and Control class on the Windows side only, the older Window classes list while it still holds classes, then Not when full screen. A magnifier shows only on this machine's side (only its windows are on screen) and fills its row: the executable joins the list, every other value replaces the field with its toggle off. Every fill sets the form's properties like typing, so the host applies it and its undo takes it back; a fill of two properties (value plus toggle) raises one change, so it is one undo step. A window without the value (a protected process's path, an untitled window, a Mac window's per-window fields) fills nothing. There is no separate "Identify window" any more.
- **Reading the window.** `WindowProbe` asks `IWindowSystem` on the UI thread (`WindowAt` and `WindowKeyAt` ask no other app anything on either platform): while dragging, the cheap `WindowKeyAt` first and `WindowAt` only when the key changes (at most every 50 ms on a platform without a key); at the release a fresh `WindowAt`. The window system is the application's `ComponentPorts.WindowSystem`, published by `FormServices.Publish` also under `--no-engine` (reading changes nothing); tests and the gallery may set `WindowSystem` instead.
- **Outside the window and coordinates.** Avalonia's pointer capture is the platform's: on Windows `SetCapture`, so moves and the release keep arriving while the button is held anywhere on screen; on macOS AppKit sends the drag and the mouse-up to the window the press was in. The position comes relative to the magnifier, far outside it, and `PointToScreen` converts it to the window system's units: **physical pixels on Windows** (per-monitor DPI aware: the client position is scaled back by the window's own scaling and offset by `ClientToScreen`, so a window on another monitor at another scale reads right) and **points from the top left of the main display on macOS** (Avalonia.Native flips AppKit's bottom-left screen coordinates; the window server's list uses the same points; `src/Augram.Platform.MacOS/README.md`).
- **No highlight frame** around the hovered window (Spy++ style), on purpose: no port gives a window's bounds, and drawing one needs a second overlay window, which invariant 6 allows only verified click-through, hidden on release and watched; that is a slice of its own with a run on Joel's machine, not something to ship unseen. The popup's text is the feedback.
