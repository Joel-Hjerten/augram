# Shell

The main window's content (F7): `Shell` renders `NavigationRegistry` as title-bar tabs with sub-tab pills, each leaf a `ScreenHost`; `SelectedKey` selects any level. `WindowDragArea` makes empty title-bar space move the window.

The find key (`EditKeymap.Find`, plan 0009 decision 6: from anywhere on the tab; Joel, Mac, 0.13.11: it needed a click in the list first) is the shell's too: `Shell` binds it through `ListEditing/ActionMenu` on the window it is attached to (`ShellAction.Find`), because Avalonia evaluates key bindings from the focused element up, and while nothing has the focus (the Mac, until a click) only the window's own. `FocusSearch` focuses the first visible `SearchBox` under the shell, which holds only the shown tab's content (no tab has two; Options has none, then nothing happens). A list that has the focus answers the key with its own binding first and marks it handled, so the shell's never fires twice; the shell's `canExecute` is the lists' `KeysEnabled` rule seen from the window: no while a text editor other than a search box (a rename editor, a form's text box) has the focus. A dialog is its own window and hosts no shell, so it is untouched (`ShellFindKeyTests`).
